# Git & Commit Conventions

## Branch Naming

```
feature/vision-editing
bugfix/sync-conflict-handling
refactor/api-client
sync/confluence-bidirectional
```

## Commit Format (Conventional Commits)

```
<type>(<scope>): <subject>
```

### Types
feat | fix | refactor | perf | test | docs | style | chore | ci

### Scopes
frontend, api, sync, db, cli, slack, config

### Subject Rules
- Imperative mood, lowercase, no period, max 50 chars
- Reference issues in footer: `Closes #123`

### Examples
```
feat(frontend): add risk severity filter
fix(sync): handle concurrent jira modifications
refactor(api): consolidate error responses
```

## PR Workflow
1. Branch from `develop`
2. Squash or rebase for clean history
3. Never force push to shared branches
