# API Conventions (Next.js)

## Route Pattern

Keep route handlers focused — extract complex queries to `lib/`:

```typescript
// --- Correct: Clean route handler ---
// src/app/api/roadmap/visions/route.ts
import { getVisions } from '@/lib/queries/visions';
import { checkReadOnly } from '@/lib/readonly';

export async function GET() {
  const visions = await getVisions();
  return Response.json({ success: true, data: visions });
}

export async function POST(req: Request) {
  checkReadOnly();  // throws 403 if NEXT_PUBLIC_READ_ONLY=true
  const body = await req.json();
  const vision = await createVision(body);
  return Response.json({ success: true, data: vision }, { status: 201 });
}
```

```typescript
// --- Wrong: 200+ line route with inline SQL ---
export async function GET(req: Request) {
  const pool = getPool();
  const { rows } = await pool.query(`
    SELECT r.*, COUNT(m.*) as milestone_count,
           json_agg(json_build_object('id', m.id, ...)) as milestones
    FROM roadmap_visions r
    LEFT JOIN milestones m ON ...
    LEFT JOIN streams s ON ...
    -- 50+ lines of SQL inline
  `);
  // 100+ lines of data transformation
  return Response.json(rows);
}
```

## Response Format

```json
{
  "success": true,
  "data": { "id": "...", "title": "..." }
}
```

Error:
```json
{
  "success": false,
  "error": {
    "code": "SYNC_CONFLICT",
    "message": "Local and remote changes conflict",
    "details": { "field": "status", "local": "InProgress", "remote": "OnHold" }
  }
}
```

## Read-Only Mode

When `NEXT_PUBLIC_READ_ONLY=true`:
- POST/PUT/PATCH/DELETE return 403
- GET/OPTIONS/HEAD allowed
- Slack API endpoints excluded

## Error Codes

| Code | HTTP | Meaning |
|------|------|---------|
| SYNC_CONFLICT | 409 | Bidirectional sync conflict |
| JIRA_API_ERROR | 502 | Jira API call failed |
| INVALID_ROADMAP | 400 | Hierarchy violation |

## DB Access

Use `lib/db.ts` connection pool — never create connections in route handlers.
