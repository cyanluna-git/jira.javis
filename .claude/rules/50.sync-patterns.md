# Sync Patterns

## Core Rule: Always Incremental

Sync must use `last_synced_at` — full-scan mirrors are forbidden.

```python
# --- Correct: Incremental sync ---
def sync_issues(since: datetime | None = None):
    jql = f"project = EUV AND updated >= '{since.isoformat()}'" if since else "project = EUV"
    issues = jira_client.search(jql)
    for issue in issues:
        upsert_issue(issue)
    update_last_synced_at(datetime.utcnow())
```

```python
# --- Wrong: Full scan mirror ---
def sync_all():
    issues = jira_client.get_all_issues("project = EUV")  # FORBIDDEN
    db.execute("DELETE FROM jira_issues")  # destroys local state
    for issue in issues:
        db.insert(issue)
```

## Conflict Detection

Local modifications must be tracked:
- `local_modified_at` — when local change happened
- `local_modified_fields` — which fields changed locally
- Compare with remote `updated` timestamp on sync

## Bidirectional Flow
1. **Pull**: Jira/Confluence -> local DB (always safe)
2. **Detect conflicts**: Compare `local_modified_at` vs remote `updated`
3. **Push**: Local DB -> Jira (only explicitly requested changes)
4. **Record**: Log all sync operations for audit

## CLI Arguments
```bash
python3 scripts/sync_bidirectional.py              # Full bidirectional
python3 scripts/sync_bidirectional.py --pull-only  # Safe pull
python3 scripts/sync_bidirectional.py --dry-run    # Simulate
```

## Rate Limiting
- Jira API: respect rate limits, exponential backoff
- Confluence API: same pattern
- Max concurrent requests: 5

## Error Handling
- Log API errors without exposing credentials
- Retry transient failures (429, 503) with backoff
- Abort on auth failures (401, 403) — don't retry
